# 경매·카드 시세 통계 설계

## 목적

홈 화면, 카드 시세 목록, 카드 시세 상세 화면이 매 요청마다 전체 경매와
입찰 데이터를 집계하지 않도록 통계 데이터를 세 가지 책임으로 분리한다.

- 진행 중인 경매 정보만 원본 `auctions`에서 실시간 조회한다.
- 완료된 날짜의 카드 시세와 입찰량은 일간 통계로 확정한다.
- 카드 목록에서 사용하는 최근 30일 누적값은 카드별 최신 요약으로 유지한다.
- 모든 날짜 기준은 `Asia/Seoul`이며 오늘 데이터는 확정 통계에서 제외한다.

## 테이블 책임

### `item_daily_statistics`

카드 한 종의 하루 종료 경매 결과를 저장한다. 카드 상세의 30일 그래프와
최근 가격 대비 상승·하락 TOP5의 비교 및 미니 그래프가 이 테이블을 사용한다.

```sql
CREATE TABLE item_daily_statistics (
    id BIGINT NOT NULL AUTO_INCREMENT,
    item_id INT NOT NULL,
    statistics_date DATE NOT NULL,
    latest_price BIGINT NULL,
    average_price BIGINT NULL,
    lowest_price BIGINT NULL,
    highest_price BIGINT NULL,
    bid_count INT NOT NULL DEFAULT 0,
    ended_auction_count INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6),

    PRIMARY KEY (id),
    UNIQUE KEY uk_item_daily_statistics_item_date
        (item_id, statistics_date),
    INDEX idx_item_daily_statistics_date_item
        (statistics_date, item_id),
    FOREIGN KEY (item_id) REFERENCES card_metadata(id)
);
```

컬럼 의미:

| 컬럼 | 의미 |
|---|---|
| `statistics_date` | 서울 시간 기준으로 완료된 날짜 |
| `latest_price` | 해당 날짜에 마지막으로 종료된 경매의 낙찰가 |
| `average_price` | 해당 날짜 종료 경매의 평균 낙찰가 |
| `lowest_price` | 해당 날짜의 최저 낙찰가 |
| `highest_price` | 해당 날짜의 최고 낙찰가 |
| `bid_count` | 해당 날짜 종료 경매에 연결된 실제 `bids` 행 수 |
| `ended_auction_count` | 해당 날짜에 종료된 경매 수 |

거래가 없는 날짜에는 행을 만들지 않는다. API가 시계열을 만들 때 가격은
직전 거래일 값으로 이월하고 입찰량은 `0`으로 채운다.

### `item_statistics`

카드마다 한 행만 유지하는 최신 30일 누적 요약이다. 카드 시세 목록과 카드
상세 상단의 요약값이 이 테이블을 사용한다.

```sql
CREATE TABLE item_statistics (
    item_id INT NOT NULL,
    as_of_date DATE NOT NULL,
    latest_price BIGINT NULL,
    average_price_30d BIGINT NULL,
    lowest_price_30d BIGINT NULL,
    highest_price_30d BIGINT NULL,
    bid_count_30d INT NOT NULL DEFAULT 0,
    ended_auction_count_30d INT NOT NULL DEFAULT 0,
    active_auction_count INT NOT NULL DEFAULT 0,
    wishlist_count INT NOT NULL DEFAULT 0,
    daily_change_rate DECIMAL(8, 2) NULL,
    weekly_change_rate DECIMAL(8, 2) NULL,
    monthly_change_rate DECIMAL(8, 2) NULL,
    updated_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6),

    PRIMARY KEY (item_id),
    INDEX idx_item_statistics_latest_price (latest_price),
    INDEX idx_item_statistics_daily_change_rate (daily_change_rate),
    FOREIGN KEY (item_id) REFERENCES card_metadata(id)
);
```

컬럼 의미:

| 컬럼 | 의미 |
|---|---|
| `as_of_date` | 통계에 반영된 마지막 완료 날짜, 정상 집계 시 어제 |
| `latest_price` | 기준일까지 가장 최근에 거래된 가격 |
| `average_price_30d` | 최근 30일 종료 경매의 가중 평균 낙찰가 |
| `lowest_price_30d` | 최근 30일 전체 낙찰가 최솟값 |
| `highest_price_30d` | 최근 30일 전체 낙찰가 최댓값 |
| `bid_count_30d` | 최근 30일 실제 입찰 수 합계 |
| `ended_auction_count_30d` | 최근 30일 종료 경매 수 |
| `active_auction_count` | 현재 `OPEN`, `ENDING` 경매 수 |
| `wishlist_count` | 현재 카드 찜 수 |

`daily_avg_price`, `daily_bid_count` 같은 일별 필드는 이 테이블에 두지 않는다.
일별 값은 반드시 `item_daily_statistics`에서 조회한다.

### `market_daily_statistics`

홈의 `30일 경매가 · 입찰량` 전용 전체 시장 일간 통계다.

```sql
CREATE TABLE market_daily_statistics (
    statistics_date DATE NOT NULL,
    average_price BIGINT NULL,
    lowest_price BIGINT NULL,
    highest_price BIGINT NULL,
    winning_price_total_30d BIGINT NOT NULL DEFAULT 0,
    highest_price_30d BIGINT NOT NULL DEFAULT 0,
    bid_count_30d INT NOT NULL DEFAULT 0,
    ended_auction_count_30d INT NOT NULL DEFAULT 0,
    bid_count INT NOT NULL DEFAULT 0,
    ended_auction_count INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
        ON UPDATE CURRENT_TIMESTAMP(6),

    PRIMARY KEY (statistics_date)
);
```

`average_price`는 카드별 평균을 다시 평균 내지 않는다. 해당 날짜에 종료된
모든 경매를 한 건씩 포함해 직접 계산한다. `_30d` 필드는 해당 기준일까지
최근 30일간 낙찰가 총합·최고가, 실제 입찰 수와 종료 경매 수다. 홈은
어제 행의 이 필드들을 마케팅 지표로 바로 표시한다. 입찰량은
`auctions.bid_count`가 아니라 각 종료 경매에 연결된 실제 `bids` 행을
집계한다.

## 화면별 조회 기준

| 화면 기능 | 조회 대상 | 기준 |
|---|---|---|
| 홈 경매 인사이트 | `auctions` | 현재 `OPEN`, `ENDING` 경매 |
| 홈 30일 경매가·입찰량 | `market_daily_statistics` | 오늘-30일부터 어제 |
| 홈 가격 변동 TOP5 | `item_daily_statistics` | 30일 내 최근 두 유효 거래 비교 |
| TOP5 미니 그래프 | `item_daily_statistics` | 오늘-30일부터 어제 |
| 카드 시세 목록 | `item_statistics` | 최신 30일 누적 요약 |
| 카드 상세 상단 | `item_statistics` | 최신 30일 누적 요약 |
| 카드 상세 그래프 | `item_daily_statistics` | 오늘-30일부터 어제 |

카드 목록과 상세 API의 기존 응답 필드는 다음처럼 매핑한다.

| API 필드 | 통계 컬럼 |
|---|---|
| `marketPrice` | `latest_price` |
| `averagePrice` | `average_price_30d` |
| `lowPrice` | `lowest_price_30d` |
| `highPrice` | `highest_price_30d` |
| `bidCount` | `bid_count_30d` |
| `history[].averagePrice` | 일간 `average_price` |
| `history[].bidCount` | 일간 `bid_count` |

## 통계 생성 흐름

서울 시간 매일 00:10에 전날 통계를 확정한다.

1. 전날 `ENDED` 경매를 카드별로 집계해 `item_daily_statistics`에 upsert한다.
2. 전날 전체 종료 경매를 집계해 `market_daily_statistics`에 upsert한다.
3. 카드별 최근 30일 일간 통계를 집계해 `item_statistics`를 갱신한다.
4. 최근 가격과 1일·7일·30일 전 가격으로 변화율을 갱신한다.
5. 현재 `OPEN`, `ENDING` 경매 수를 `active_auction_count`에 반영한다.

동일 카드와 날짜는 유니크 키로 보호하므로 같은 집계를 다시 실행해도 행 수가
증가하지 않는다. 입찰 발생 시마다 30일 데이터를 재집계하지 않으며, 원본
경매와 입찰에는 거래 사실만 기록한다.

## 가격 및 변화율 기준

- 낙찰가는 `ENDED` 경매의 `current_price`다.
- 최종 `WON` 입찰가와 경매의 `current_price`는 일치해야 한다.
- 하루 최신 가격은 `close_time`, 경매 ID 내림차순으로 마지막 경매를 선택한다.
- 변화율 기준 가격이 없거나 0이면 `0.00`으로 저장한다.
- TOP5는 최근 두 거래 가격이 모두 양수이며 동일 가격은 제외한다.
- 상승은 변동률 내림차순, 하락은 변동률 오름차순으로 정렬한다.

## 초기 데이터

초기 데이터는 FK와 실제 서비스 흐름에 맞춰 파일명 순서로 실행한다.

```text
required-data/
├── 001-pokemon-card.sql
├── 002-user.sql
└── 003-auction-bid-item-statistics.sql
```

`003`은 경매를 먼저 생성하고 입찰을 생성한 뒤, 동일한 집계 규칙으로 세 통계
테이블을 구성한다. 화면에는 오늘을 제외한 30일을 제공하지만 1일·7일·30일
비교 기준을 확보하기 위해 초기 데이터 원본은 32일을 생성한다.

## 검증 기준

- 같은 카드와 날짜의 일간 통계가 중복되지 않아야 한다.
- 일간 가격·입찰 수가 실제 종료 경매와 입찰 행에 일치해야 한다.
- 30일 최저·최고·평균·입찰 합계가 일간 통계와 일치해야 한다.
- 오늘 거래가 홈, TOP5, 카드 상세 시계열에 포함되지 않아야 한다.
- 그래프는 누락 없이 30개 날짜를 반환해야 한다.
- 무거래일은 가격을 이월하고 입찰량을 0으로 반환해야 한다.
- TOP5 표시 가격과 미니 그래프 마지막 점은 같은 최근 거래 데이터여야 한다.
- 초기 SQL을 다시 실행해도 경매·입찰·통계 행 수가 증가하지 않아야 한다.
